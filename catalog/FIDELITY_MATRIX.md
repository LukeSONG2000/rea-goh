# 保真度矩阵：忠实度分级 / 反编译盲区 / 获取途径

## 一、忠实于原架构/语言吗？（分层诚实回答）

| 层 | 忠实度 | 说明 |
|---|---|---|
| **资产（模型/贴图/动画/图标）** | ★★★★★ 1:1 | 原文件提取重组，仅容器转换（GLB）；动画=游戏自己的状态机剪辑 |
| **UI 美术** | ★★★★★ 1:1 | 原版 NGUI 图集按 m_Rect 精确切片（60k 张），零自绘 |
| **战斗算法** | ★★★★☆ 算法 1:1 | 逐条从反编译移植（回合 tick/伤害管线/暴击/减伤/播种/修正聚合/属性聚合），每条带 RVA 出处；RNG 与 JDK 位级一致 |
| **语言** | Unity 产品层 = **C#（与原版同语言）**；研究/离线层 = Python | C# 是重实现（取算法语义），不是还原原版 OOP 类图（EffectContext/DI 管线未照抄——行为等价但结构简化）|
| **引擎** | 同引擎（Unity），LTS 版本（可升级 6000.3）| 资产管线同源 |
| **战斗常数** | ★★☆☆☆ 占位中 | 数据驱动字段待运行时真值（扫描器就绪）；硬编码 9 项已是真值 |
| **UI 布局** | ★★☆☆☆ 测量 | 原版 UI prefab 不在本地缓存 → 按截图测量（已标注 REFERENCE-MEASURED）|
| **UI 架构** | ★☆☆☆☆ 重实现 | 原版 NGUI → 我们用 uGUI（贴图忠实，框架换代）|
| **服务器系统** | 不适用 | 进度/经济/社交是服务端，源码已丢失且不在线上抓取 |

## 二、反编译文件里没有的东西（六大盲区）

| 盲区 | 性质 | 弥补途径 |
|---|---|---|
| 1. **方法体**（199,578 个方法只有签名+地址）| 不是缺失，是"未做"——Ghidra 逐个反编译（已做 ~25 个核心）| 自做（无社区来源）；按需定点 |
| 2. **数据驱动 GameConstants 真值**（暴击基数/等级系数/减伤偏移等 12+ 项）| 不在磁盘任何地方——运行时从 config 响应水合 | ✅ **运行内存读取**（扫描器已建自测通过，游戏登录一次即得）；社区无公开镜像 |
| 3. **UI prefab 布局** | 运行时 CDN 下发，本地无 | ✅ 内存读取理论上可行（对象图，难度高）；现实=截图测量（已做）+ NGUI 图集切片（已做）|
| 4. **gamedata 镜像滞后**（104 角色名缺失等）| 社区镜像略落后 0.40.7 | ✅ **社区提供**：swgoh-utils/gamedata 更新后重跑 build_names.py |
| 5. **原版字体** | 动态字体 payload 无效（EmptyFont 存根）| ✅ 社区相似字体（Exo 2/Roboto Condensed 级）|
| 6. **服务器独占系统**（进度/经济/抽卡/社交）| 在线服务端，本地+反编译均无 | 不复现（离线单机不需要）；社区无 |

## 三、可行性结论

- **内存读取**：GameConstants = ✅ 首选路径（扫描器已就绪，游戏登录一次自动抓真值，含 30+ 附加常数族）；UI 对象图 = 可行但高成本，仅当截图测量不够时再做
- **社区提供**：gamedata 滞后 ✅、字体 ✅；GameConstants/UI prefab ✗（无公开来源——这就是自研逆向的价值）
- **总纲**：反编译文件里没有 ≠ 拿不到——分层处理：磁盘有的提取、内存有的读取、社区有的借用、真没有的测量或自建并申报
